# Go 后端工程规范

版本：1.0 · 日期：2026-10-06  
适用范围：`apps/api/**`  
技术基线：Go、Gin；现有 TeamFlow 数据访问实现按已核验的代码与契约维护

本文规定 Go 业务后端的模块边界、依赖方向、HTTP、安全和失败处理要求。本文描述目标及强制工程要求，不代表尚未实现的能力已经交付。与仓库根 `AGENTS.md` 冲突时服从根规则。

## 1. 运行边界

- Go 是 TeamFlow 唯一公开业务入口，并负责提供嵌入的 React SPA 静态产物。
- `/api/v1/*` 是公开业务 API。Python Agent 只在未来真实 RAG 阶段作为内部运行时，由 Go 内部客户端访问；浏览器不得直连 Python。
- 首版包含 TeamFlow 核心协作和公开静态 RAG 预览；静态预览不调用业务 API。真实 RAG 接入另阶段设计和验收。
- Go 独占用户、团队、成员、项目、任务、授权等平台数据的写入。未来 RAG 接入时，Python 继续独占其 Agent 会话、消息、决策日志、文档、切片及索引。Go 不直接访问 Agent 表。

## 2. 模块结构与公开接口

按业务能力组织代码，允许结合现有结构逐步演进：

```text
cmd/api/                  # 进程入口、依赖组装、优雅关闭
internal/
  auth/                   # 身份验证及登录用例
  team/                   # 团队和成员规则
  project/                # 项目和项目成员规则
  task/                   # 任务规则与状态流转
  platform/               # HTTP 路由、静态文件、进程级接线
  ...                     # 基础设施适配器按职责归属
api/                      # OpenAPI 与公开契约
migrations/               # 有编号、可审查的 SQL 迁移
```

模块对外提供小而稳定的应用接口、领域类型和必要 DTO。跨模块协作只能使用公开接口；禁止导入其他模块的私有文件、handler、repository 或 ORM 模型。不得为假设中的替换点提前增加空洞接口；只有存在真实替代实现或需要隔离的外部边界时再定义端口。

处理器/路由负责 HTTP 输入解析、边界校验、调用用例和映射响应；用例负责业务流程、授权决策及事务边界；领域代码表达稳定业务规则；Repository/客户端等适配器负责数据库或外部协议。入口负责构造依赖并注入，业务模块不得自行创建全局数据库、Redis 或 HTTP 客户端。

## 3. 依赖方向

```text
cmd / platform 组装层
    ├── HTTP Handler → 应用用例 → 领域规则
    └── 基础设施适配器 ───────────┘
```

- 依赖指向稳定业务规则；领域和应用层不得依赖 Gin、GORM、Redis、RabbitMQ、网络协议或供应商 SDK。
- 端口由需要能力的应用/领域模块定义，适配器在外层实现；接口只暴露该模块必需的最小操作。
- 禁止循环依赖、模块间深层导入、跨模块直接查表和通过共享可变全局状态协作。
- HTTP DTO、数据库模型和领域类型分开管理；跨边界通过显式映射，避免持久化细节泄漏到业务契约。
- `context.Context` 从请求/任务入口向下传递；不得存入长期对象，不得无故丢弃取消信号。

## 4. 鉴权与授权

- 每个受保护请求必须在业务执行前验证凭据；解析失败、过期或缺失身份时立即以正确状态结束请求，不读取 claims、不继续调用后续 handler。
- 认证回答“调用者是谁”；授权由服务端用例根据团队/项目成员关系、资源归属和动作规则判定。客户端 ID、隐藏按钮及路由守卫都不可信。
- 所有读取、写入、列表、分页、计数和关联加载均须限定当前调用者有权访问的团队/项目范围。先授权资源，再执行变更；不可仅依赖前端传入的父资源 ID。
- 新建、添加成员、角色变更、负责人分配、状态转换和删除等操作分别检查动作权限及目标资格。最后一个所有者等不变量必须在服务端强制。
- 对失效身份返回 401；身份有效但权限不足返回 403。资源是否存在会造成枚举风险时，按公开契约统一为不可见响应。
- 首版浏览器 Access Token 只在内存，刷新页面要求重新登录，不实现静默刷新。前端退出清除本地令牌/缓存并取消请求，不调用服务端令牌撤销；服务端仍按令牌有效期和逐请求资源授权保护资源。不得把此行为写成“退出即吊销”。
- 密钥、令牌和密码不得进入日志、URL、错误详情或仓库。密码校验使用当前项目已批准且安全的实现；不得自行发明加密方案。

## 5. HTTP 契约、校验与错误

- API 前缀 `/api/v1`；JSON 字段遵循现有 OpenAPI/TeamFlow 契约，变更先核对实际调用方并同步 OpenAPI、客户端 DTO 和说明。
- 在 HTTP 边界校验路径、查询、分页、枚举、字符串长度、请求体大小和必需字段；校验不能替代用例中的业务不变量。
- 错误映射为稳定机器可读错误码、适当 HTTP 状态和可安全展示的消息，并包含 `request_id`。不得把全部错误返回 200、直接暴露 SQL/堆栈/内部凭据或把失败伪装成空成功。
- 预期业务拒绝使用可辨识的领域错误；适配器错误保留因果链并在边界分类。日志记录去敏上下文和关联 ID，不默认记录完整请求正文。
- Gin middleware 若写出错误响应，必须立即终止请求链。错误不得重复写响应，也不得在鉴权失败后继续执行。
- SPA 托管路由须区分 API、静态资源与前端路由。未知 API 返回 JSON 404；不存在的文件返回 404；仅前端深层路径回退 SPA 入口。

## 6. 数据与事务

- 数据库访问经所属模块 Repository；查询和更新始终附带授权作用域。禁止跨模块直接访问其他模块表或让 Go 与 Python 写同一业务表。
- 数据库迁移采用有序、可审查脚本；禁止生产启动时由 AutoMigrate 静默修改结构。约束在数据库层兜底唯一性与关键不变量。
- 所有数据库操作传递 context。事务保持短小，只包含本地原子变更；外部网络调用不得放进长事务。
- 分页必须有上限；排序列使用白名单；用户输入不可拼接到 SQL 结构。写冲突和并发版本错误应转换为明确契约错误。
- 不可恢复的迁移需提供升级前备份、验证和回退策略；不以删除数据作为故障恢复手段。

## 7. 外部调用、并发与生命周期

- 外部 HTTP 客户端复用连接并设置连接/整体超时、响应体限制和取消传播；按幂等性区分重试策略。创建、任务提交或结果未知的写操作禁止盲目重试。
- Go 到 Python Agent 的客户端只能由专属内部适配模块承载，业务 handler/service 不拼接 Agent URL、不暴露内部 ID。真实 RAG 接入须先有独立契约、内部鉴权、超时和回滚设计。
- 每个 goroutine、定时任务和订阅必须有所有者、退出条件、取消路径和错误观测；服务关闭时停止接收、取消工作并有界等待。
- 并发控制和数据一致性以数据库约束/事务为权威；Redis 只可作辅助协调，不可成为唯一业务事实源。

## 8. 日志与隐私

- 请求与后台工作使用稳定关联 ID；日志采用结构化字段并对用户输入、外部响应和模型输出做最小化与脱敏。
- 禁止记录密码、完整令牌、Cookie、密钥；默认不记录任务正文、完整问题、文档或回答。
- 管理审计记录必要的操作者、对象、动作、时间与结果，不把审计权限等同于查看用户内容的权限。

## 9. 验证门禁

涉及 Go 代码的交付至少执行并如实报告：

```powershell
gofmt -w <本次变更的 Go 文件>
go vet ./...
go test ./...
go build ./...
```

若变更 API 契约，还要校验 OpenAPI 与实际 DTO/状态/权限一致；若变更数据结构，还要验证迁移及恢复路径。鉴权变更需覆盖无效/过期凭据、未授权团队/项目和 middleware 终止行为。未运行的检查不得声称通过，环境阻塞须记录命令和原因。

文档-only 决策更新不需要运行 Go 或前端构建；实现对应任务时执行其完整门禁。
