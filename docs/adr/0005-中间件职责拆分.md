# ADR-0005：中间件职责拆分

- 状态：已采纳
- 日期：2026-11-24
- 范围：`apps/api` 的 Gin 中间件实现与依赖组装

## 背景

请求 ID、请求体限制和 panic 恢复集中在 `internal/infrastructure/platform/response.go`，认证中间件依赖完整的 `auth.Handler`。它们分别与依赖组装及注册/登录 HTTP 处理器绑定，不利于独立复用。此前将中间件实现放在组装层或认证处理器的约定由本决策替代。

## 决策与备选方案

在 `internal/infrastructure/middleware` 中集中实现 `RequestID`、`BodyLimit`、`Recovery` 和 `Authenticate`。`platform` 负责构造依赖、安装中间件和调用模块路由注册。HTTP 上下文键、响应信封与错误映射仍归 `httpx`；JWT 签名校验与 Redis 会话校验仍通过现有认证用例完成。

认证中间件定义消费端最小接口 `Authenticator`，仅含 `Authenticate(context.Context, string) (*auth.Identity, error)`。接口隔离认证用例并支持现有测试替身；中间件不导入 `auth/handler`、`auth/service` 或认证仓储，不自行访问 Redis 或校验 JWT。

- 保持现状：实现仍与组装或完整 HTTP Handler 绑定，未采用。
- 只移动文件、让新包依赖 `auth/handler.AuthHandler`：会反向依赖具体 HTTP 适配并扩大接口，未采用。
- 同时整理所有业务 DTO、共享错误与 `httpx` 的 Agent 错误依赖：属于更大范围的模块边界调整，单独处理。

## 依赖方向与数据所有权

```text
platform → middleware → httpx / auth.Identity / Authenticator
         → auth.Handler（公开注册与登录路由）
         → AuthService（注入 Authenticator 的实现）
auth.Handler.Middleware → middleware.Authenticate（兼容转发）
```

`middleware` 不依赖 `platform`，不创建连接、后台任务或共享可变状态。业务授权仍由团队、项目、任务和聊天用例负责，数据所有权不变。`httpx` 当前仍间接引入 `chat/repository` 的 Agent 错误分类；本次保留该既有依赖，不宣称 HTTP 工具已完全独立于业务适配器。

## 安全影响与兼容迁移

全局顺序保持 `Recovery → RequestID → BodyLimit`，限制仍为 1 MiB，作用于全部请求；认证仍仅安装到受保护的 `/api/v1` 路由组。保持请求 ID 白名单、日志脱敏、认证失败终止、401/503 分类及用户 ID 注入行为。响应写出后的 panic 不追加 JSON，以保留 SSE 行为。请求体限制只包装读取器，不新增统一 413 响应；绑定失败仍由现有 Handler 映射。

现有测试直接调用 `platform` 私有函数和 `auth.Handler.Middleware()`。按仓库本次不得修改测试文件的约束，只保留测试所需的请求 ID、恢复及认证薄转发入口，实际实现唯一位于 `middleware`；生产组装直接使用新包。后续允许迁移测试调用点时再删除这些入口。公开 API、配置、数据库结构和依赖版本不变。

## 回滚方案

成组恢复本次新增包、安装点、兼容入口和文档变更，不恢复整个工作区，不覆盖其他未提交改动；无需数据或配置回滚。

## 验证证据

2026-11-24 在 `apps/api` 完成：

- 七个变更 Go 文件执行 `gofmt -w`；`go vet ./...`、`go test -count=1 ./...`、`go build ./...` 均通过。
- 通过临时 `go run` 程序构造 Gin 内存请求，共 20 个场景通过：请求 ID 合法值保留、注入/超长/空值/空格拒绝，日志器与响应 ID 传播；未知 Content-Length 下空体、低于/等于/超过 1 MiB；响应未写出时统一 500、SSE 已 Flush 后不追加 JSON；缺失/错误 scheme/空 Bearer/无效/过期令牌、被替换会话、认证后端故障、正常及大小写混合 scheme。认证失败时后续处理器均未执行，公开路由组不受认证中间件影响。
- 认证场景使用真实 JWT 签名器及现有认证用例，会话存储为内存替身；未连接真实 MySQL、Redis 或 Python Agent，不代表真实依赖端到端验收。
- 九个现有 `_test.go` 文件的 SHA-256 与本任务开始时一致，未新增测试文件。临时验证程序执行后已清理。
- 包导入检查确认新中间件包无 `platform`、`auth/handler`、`auth/service` 或认证仓储的直接依赖；`httpx` 既有间接依赖仍按上述边界保留。
