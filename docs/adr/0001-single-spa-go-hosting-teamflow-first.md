# ADR-0001：单一 SPA、Go 托管与首版业务边界

- 状态：已采纳
- 日期：2026-10-06
- 决策范围：首版应用入口、网页托管、TeamFlow 与 RAG 边界、登录行为及数据所有权

## 背景

仓库同时包含 React RAG 页面、TeamFlow Go 协作后端及 Python RAG Agent。原基线将团队协作排除在首版范围之外，并要求 Nginx 作为唯一公开入口；这与当前交付目标不符。为避免双 SPA、浏览器直连 Agent 或 Go/Python 争写数据，需要明确首版边界和统一入口。

## 决策

1. 前端采用一个 React 19 SPA，React Router basename 与 Vite base 均为 `/`。协作应用使用根路由；五个既有 RAG 页面归入公开 `/rag/*` 路由。旧地址可按迁移清单兼容跳转。
2. Go 是唯一公开业务入口，并托管 Web 构建产物。浏览器同源访问 Go 提供的页面与 `/api/v1`；Go 处理 API，并在真实 RAG 阶段通过受限内部 HTTP/SSE 接口访问 Python Agent。开发时 Vite 仍可代理 API。Nginx 可作为可选部署组件或边缘代理，但不是架构要求中的唯一公开入口。
3. 首版交付 TeamFlow 核心协作流程（登录、团队/成员、项目/项目成员、任务管理）及公开静态 RAG 预览。静态预览不调用业务 API、不执行真实检索。真实 RAG 身份接入、知识库授权、上传、问答、引用与 Python Agent 调用属于后续阶段，不作为首版验收条件。
4. Go 独占 TeamFlow 平台数据的写入权，包括用户、团队、成员、项目、任务、权限和登录相关数据。Python 仅在后续真实 RAG 接入后，继续独占其既有 Agent 会话、消息、决策日志、知识库文档、切片与检索索引数据。Go 不直接读写 Python 数据表；跨运行时只通过稳定的内部接口交互。两方不得写同一业务表。
5. 首版登录凭据只保存在浏览器内存，不写入 localStorage、sessionStorage 或 URL。页面刷新会丢失令牌并要求用户重新登录；首版不实现静默刷新。前端退出只取消活动请求、清空内存令牌及用户敏感缓存，不调用服务端撤销令牌；已签发令牌仍按服务端有效期/既有服务端登录策略失效。服务端撤销语义若未来变更，须另行决策并同步契约。

## 依赖方向与边界

```text
React SPA → Go 公开 HTTP API / Go 静态网页托管
                         │
                         └── 后续真实 RAG：内部 AgentClient → Python Agent
```

Go 模块依赖由启动组装层指向业务模块；Handler 依赖应用用例，应用用例依赖领域规则及小型端口，基础设施适配器实现端口。领域和应用规则不得依赖 Gin、GORM、Redis、队列或供应商 SDK。Python Agent 不成为浏览器公开服务。

## 数据所有权

| 数据 | 唯一写入方 | 访问方式 |
| --- | --- | --- |
| 用户、团队、团队成员、项目、项目成员、任务、授权及平台会话 | Go | Go 业务模块和平台存储 |
| Agent 会话、消息、决策记录、RAG 文档/切片/索引 | Python（真实 RAG 后续阶段） | Go 经内部 AgentClient 请求；不直接访问 Agent 表 |
| 静态 RAG 预览状态 | 无服务端业务数据 | SPA 本地展示，不连接真实 RAG |

## 鉴权、安全与失败处理

- Go 对所有业务 API 执行身份校验和资源归属/动作授权；前端路由和按钮隐藏不构成授权。
- 无效或过期令牌返回明确的未认证错误，不继续执行处理器。数据访问必须在查询边界应用团队/项目作用域。
- 令牌只保存在内存带来刷新后重新登录的体验约束；已签发令牌退出后仍可在其有效期内使用，服务端必须继续执行到期及资源权限检查。首版不得把前端退出描述为服务端令牌吊销。
- API 错误使用稳定错误码及真实 HTTP 状态，内部错误详情留在去敏日志并关联 request_id。外部依赖错误不得伪装成功。
- Go 网页托管需区分 `/api/*`、存在的静态资源和 SPA 深层路由：未知 API 返回 JSON 404，不存在资源返回 404，其余有效前端路径回退入口 HTML。

## 备选方案

- 两个独立 SPA：拒绝，增加入口与导航/发布复杂度，且不符合一个应用的目标。
- Nginx 必须作为唯一网页入口：拒绝，Go 已是唯一公开业务入口，Go 托管产物可直接形成一致发布包；边缘代理仍可选用。
- 首版即接入 Python RAG：拒绝，扩大首版范围并把数据授权、Agent 可用性和隔离验证变成首版依赖；真实接入单独阶段设计和验收。
- 浏览器持久化令牌并提供静默刷新：拒绝，与首版内存令牌、刷新重新登录的安全和产品约束不符。

## 迁移与回滚

- 将现有五个 RAG 页面挂接 `/rag/*`，保留页面静态预览标识和不调用业务 API 的边界。
- 构建顺序为 Web 后 Go；Web 产物通过 `go:embed` 纳入 Go 发布包。部署可保留 Nginx 作为可选反向代理，但健康、API、静态资源与深层路由需由 Go 本身支持。
- TeamFlow 代码迁入 `apps/api` 时保留其数据和 Git 历史，使用独立开发数据库；不覆盖已有数据库或 Python RAG 数据。
- 路由或托管回归时可回退发布包/路由配置；数据归属不迁移、不清库。真实 RAG 接入必须单独定义可回退映射和对账方案。

- 本 ADR 与 `docs/2026-10-05-rag-teamflow-任务清单.md` 的首版范围、`/rag/*` 路由、Go 托管和登录规则对齐。
- 产品与技术文档同步明确 TeamFlow 首版范围、真实 RAG 后置、Go/Python 唯一写入边界及非 Nginx 独占入口。
