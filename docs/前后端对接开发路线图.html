第 0 阶段 · 现在

契约核准

消除文档与实现之间的歧义

前后端共同完成

  • 重新采集 FastAPI 运行时 OpenAPI，与 handler、Web client 和仓库 YAML/JSON 对照。
  • 校正状态码、字段约束、分页上限、错误体和代理目标；标注 Python 现状与 Go 目标。
  • 列出破坏性迁移项：路径、envelope、字符串平台 ID、鉴权、分页及引用定位。
验收契约源、迁移说明和 Web DTO 对齐；未决权限规则与数据源/日志/检索实验台范围有明确决策记录。
第 1 阶段 · 首版

TeamFlow API

先构建核心协作业务闭环

Go 先行，Web 按契约接入

  • Go 实现认证、团队/成员、项目/成员、任务及逐请求资源授权；事务与唯一约束由 Go 平台模块负责。
  • 更新 apps/api/openapi.yaml/json，明确 DTO、权限、错误码、分页与状态码。
  • Web 逐 feature 接入已落地 API；登录令牌只在内存，Query key 包含身份/工作空间作用域。
验收“登录 → 建团队 → 添加成员 → 建项目 → 管理任务”可端到端完成；跨团队访问拒绝，前后端门禁通过。
第 2 阶段 · RAG 基础

授权与映射

先建立可信的服务边界

Go 控制访问，Python 保持 Agent 写入权

  • 设计 workspace、知识库权限与 Agent 资源映射；明确内部鉴权、超时、失败分类和未知结果对账方式。
  • 提供知识库与文档映射能力，所有查询绑定 workspace/资源权限；Go 不跨库查写 Agent 表。
  • 统一公开 ID、错误 envelope、平台数据所有者和审计边界。
验收未授权知识库、他人文档与跨 workspace 请求均被拒绝；空授权集合绝不转为全库查询。
第 3 阶段 · RAG 闭环

会话与 SSE

先跑通最小真实问答旅程

会话 → 授权问答 → 引用 → 历史

  • 接入会话创建/列表/历史和 POST /chat/sessions/{id}/runs；Go 计算授权 KB ID，浏览器不传内部 Agent 参数。
  • 实现 SSE 缓冲解析、Unicode/半包、多事件、序号、取消、error 与无 done EOF；只有 done 才标记完成。
  • 将引用改为授权范围内稳定 document/chunk ID 定位；不复刻按全局文件名查找的旧接口。
  • Web 以 fetch + ReadableStream 使用 POST SSE；完成后以服务端历史为准刷新 Query。
验收真实 Agent 授权问答、引用和历史可用；同会话并发、断流和越权测试通过；不承诺未经验证的 Python 计算取消。
第 4 阶段 · 独立交付

可靠入库

需求确认后再引入队列保证

从过渡轮询走向可恢复任务

  • 短期可采用 Go 接旧上传并轮询状态，明确 Python 重启可能中断的限制。
  • 可靠阶段需 Python 支持 job_id 幂等提交/查询/复用；再实现 Go ingestion_jobs + outbox、RabbitMQ Confirm、Worker、租约、重试、死信与对账。
  • 删除与重试须有幂等键/版本防护；网络结果未知进入 reconciling，不盲目重放。
验收重复投递、Worker 崩溃、Agent 已成功但响应丢失、删除竞态和重试均可恢复；没有 Python 幂等接口前不宣称可靠或 exactly-once。

共同门禁与主要风险

每个阶段同步代码、契约、验证证据和运行说明。

阶段完成前必须验证

  • 前端：npm run typecheck、npm test、npm run build；用户旅程变化加 npm run test:e2e。
  • Go：gofmt、go vet ./...、go test ./...、go build ./...。
  • 契约变更校验 OpenAPI 与真实 DTO/状态/权限；数据变更验证迁移和恢复路径。
  • 越权、空 KB 权限、取消、未知结果、错误终态和数据隔离均有对应测试。

当前计划需避免的偏差

  • 不要把迁移文档中的目标 API 写成已上线能力。
  • 不要同时让 Go 与 Python 写同一类事实数据；Agent 表由 Python 持有。
  • 不要盲目重试创建会话、问答、上传等结果未知的写操作。
  • 不要复刻全局文件名引用查询、无鉴权管理端点或静默吞错的检索降级。
  • React 迁移计划中的 API 占位只能明确失败，不能用静态假数据伪装服务端成功。
