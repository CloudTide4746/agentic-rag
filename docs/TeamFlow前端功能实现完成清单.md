# TeamFlow 前端功能实现完成清单

> 本清单细化 Team、Project、Task 三个前端功能的实现与验收事项。所有接口字段、路由和权限语义以当前 `apps/api` 实现及其 OpenAPI 为准；本文中的页面组织是实现目标，不代表接口已经可用。

## 2026-11-24 最小可运行演示接入

本轮范围是当前 `apps/api` 已公开的认证、Team/Project/Task CRUD 和聊天接口，不扩展旧 TeamFlow 的成员、评论、附件、通知接口。原清单保留为完整验收目标，下面记录本轮已实现和真实验证范围，不将全部清单自动勾选为完成。

- 已实现注册、登录、内存令牌、退出、401 回登录和返回原页面。刷新页面需重新登录；退出只清理客户端状态，不吊销服务端令牌。
- 已实现团队、项目、任务的真实分页列表、详情、创建、修改、删除；分页在 URL，按用户及父资源限定 Query key。读请求与写请求均可取消，写失败不自动重放。
- 团队和项目修改/删除依据 owner 展示，后端仍独立鉴权。跨团队项目、跨项目任务在详情请求后校验父资源。删除需要显式确认。
- 任务更新携带当前 `version`；409 保留输入、禁止用旧版本重复提交，显式重新读取后编辑。状态与负责人只读；当前公开后端没有对应专项更新接口。
- 聊天使用 Go `/api/v1/chat/*`，支持分页会话、新建、历史、流式回答、引用文字、阶段数据、耗时/token 和停止接收。远端会话及消息由 TanStack Query 唯一持有；Zustand 仅保存当前流与阶段交互。成功终态后刷新历史，以服务端正文为准。
- SSE 校验已覆盖分片 CRLF、Unicode、多事件、多行 data、未知事件、异常 JSON/字段、done、error、无终态 EOF。取消只承诺停止客户端接收，不能证明模型停止。
- `apps/web` 的 `/api` 默认代理到独立本地 Go `18080`，可用 `API_PROXY_TARGET` 覆盖。浏览器不携带内部 Agent 凭据、不直连 Python。

### 验证证据

- `npm run typecheck`、`npm run build` 通过（构建存在主包超过 500 kB 的提示）。
- `npm test`：8 通过、4 失败。失败均来自现有 `router.test.tsx` 对旧公开静态聊天/协作占位页面与示例链接的预期；现在对应真实认证流程。按仓库规则未新增或修改测试文件。
- `npm run test:e2e -- --workers=1 --reporter=line`：4 个用例均在启动浏览器时失败，缺少 Chromium headless shell 1243；没有完成浏览器验收。现有用例仍包含旧静态数据/无业务请求断言，后续需用户明确授权后更新测试。
- 用临时内存脚本运行真实 React DOM（jsdom，非浏览器）与本地真实 Go HTTP：登录跳转、创建团队→创建项目→创建任务、进入详情、修改任务、模拟并发 409 并保留输入、显式重读、删除任务、聊天入口、退出跳转通过。
- 用前端实际 API 适配器联调真实 Go：团队/项目/任务完整 CRUD、列表/详情、401/403/409、会话列表通过。测试只创建临时团队/项目/任务，并依次删除；未修改原有业务内容。
- 临时脚本的 SSE 协议和流状态检查通过，包括取消和退出后不再写入旧流。它们不能替代真实模型端到端验证。
- 同时执行现有 Go `go vet ./...`、`go test ./...`、`go build ./...`，均通过；本轮未修改 Go 业务逻辑。

### 剩余边界

本机 Python Agent 8000 未运行，当前 Python 环境缺少 FastAPI/Uvicorn 等运行依赖，`backend/.env` 也没有模型密钥配置；未调用真实模型、未产生生成为目的的费用。聊天界面接入和异常路径已完成，真实模型问答仍未验收。

知识库/上传/重试/切片、数据源配置、检索测试与历史决策日志仍为公开静态预览；当前 Go 没有这些公开管理端点，不能用旧路径或直连 Python 伪装已接入。知识库授权映射、引用定位、任务状态/负责人操作和成员管理属于后续后端契约工作。

项目日期与任务截止时间可以设置或修改，当前后端不支持清除已有日期，表单会明确说明。团队/项目软删除不会清空其下级业务记录。真实浏览器视觉与交互效果由用户手动验证。

## 使用方式

- 按「契约准备 → Team → Project → Task → 集成验收」顺序推进；每项完成后勾选，并记录关联 PR、测试或验收证据。
- 如果后端契约尚未实现或存在歧义，先记录缺口并确认接口，不在前端猜字段、伪造成功状态或用 mock 代替真实集成。
- 成员管理、归档、删除、批量操作等只有在产品范围和后端契约均确认后才纳入；未确认的能力明确标为后续，不阻塞已确认的核心闭环。

## 5. 阶段完成定义

### Team 阶段

- [ ] 用户能查看并创建 Team，能选择当前 Team；成员操作仅在后端契约支持且纳入范围时验收。
- [ ] 空态、错误、重试、权限拒绝和 Team/用户切换缓存隔离均有测试证据。

### Project 阶段

- [ ] 用户能在当前 Team 下查看、创建并打开 Project；URL 筛选/分页按已确认范围可恢复。
- [ ] Team 与 Project 的权限边界、服务端校验错误及 mutation 缓存一致性均有测试证据。

### Task 阶段

- [ ] 用户能在当前 Project 下创建、查看、分配并更新 Task 状态。
- [ ] 分页/筛选可恢复，失败路径明确，版本冲突不会静默覆盖其他人的更新。

### 整体交付

- [ ] 主用户旅程与关键失败旅程通过自动化测试。
- [ ] 前端质量门禁通过，API/OpenAPI 与页面契约一致，剩余未验证项和范围外能力已记录。
