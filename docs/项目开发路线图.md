# 企业内部知识库问答平台：项目开发路线图

日期：2026-09-21  
状态：规划中，作为后续所有开发工作的总纲

## 1. 文档用途与最终目标

本文安排整个项目的开发框架、阶段依赖、交付物和验收目标，不展开到逐文件、逐函数的实现步骤。每次开始一个阶段时，再根据当时的代码状态细化具体任务。

最终交付一个可部署、可演示、可测试，并且能在简历和面试中解释清楚的企业内部知识库问答平台：管理员管理成员、知识库和文档；员工在授权范围内提问，获取流式答案和引用证据；系统提供处理任务、运行记录、反馈和统计。

执行依据为仓库根 AGENTS.md、开发规范与技术选型文档，以及 apps/web、apps/api 中各自的详细工程规范。发生冲突时按仓库规定的优先级处理。

## 2. 技术与职责边界

| 部分 | 固定技术 | 主要职责 |
| --- | --- | --- |
| 前端 | React 19、TypeScript、Vite、React Router、Tailwind CSS | 页面、交互、路由与展示 |
| 前端状态与图表 | Zustand、TanStack Query、ECharts | 流式草稿、服务端缓存、统计图表 |
| 业务后端 | Go、Gin、GORM | 认证授权、业务规则、资源映射、接口与流式转发 |
| 业务存储 | MySQL、Redis | 持久化、登录状态辅助、限流和缓存 |
| 异步任务 | RabbitMQ、Go Worker | 文档任务调度、重试、对账和恢复 |
| AI 运行时 | 现有 Python Agent、Elasticsearch | Agent 编排、解析、检索、模型调用与 RAG 数据 |
| 部署 | Docker Compose、Nginx | 环境复现、内部网络和单机演示部署 |

核心调用关系：React → Go API → 内部 Python Agent。浏览器不直接访问 Agent。

Go 独占平台数据写入；Python 保留消息、决策日志、文档切片和索引等 RAG 数据的写入权。Go 经接口使用 Agent，不直接读写 Agent 表。

保留现有 Agent 核心算法与提示词。先通过已有接口完成业务闭环；后续可靠任务需要的幂等适配层单独设计、评审和实施，不能假定 Docker 封装后就自然具备可靠性。

首版采用单企业部署。平台保留 workspace 作用域，但没有通过 Agent 全链路隔离验证之前，不开放或宣传多租户能力。

## 4. 总体开发顺序

```text
阶段 0：基线与契约确认
    ↓
阶段 1：登录、权限与应用框架
    ↓
阶段 2：已有知识库上的真实流式问答 → 首个可演示版本
    ↓
阶段 3：知识库、上传、引用与删除闭环 → 业务 MVP
    ↓
阶段 4：可靠异步任务与故障恢复
    ↓
阶段 5：成员管理、反馈、运行记录与统计
    ↓
阶段 6：安全加固、部署与全链路验收 → 可交付版本
    ↓
阶段 7：评测、性能证据与简历材料 → 作品集版本
    ↓
阶段 8：按需求选择高级扩展
```

这是验收顺序，不表示测试、安全和部署都等到最后才做。每阶段同步补测试与文档；开发依赖环境从阶段 0 开始准备，阶段 6 完成统一发布验收。

## 5. 各阶段安排

### 阶段 0：确认基线、接口和开发环境

**目标：** 确定现有能力真实可用，新旧系统之间的边界足够清晰。

- [ ] 核验前后端现有依赖锁定文件、启动方式和基础测试，保留当前工程。
- [ ] 确认 Python Agent、模型服务、MySQL 和 Elasticsearch 的运行条件。
- [ ] 用非敏感演示资料记录旧 Agent 的一次完整问答、引用及消息历史。
- [ ] 整理内部 HTTP/SSE 契约，重点确认生成内容是否存在替换、重写行为。
- [ ] 确认平台库与 Agent 库的账号、资源映射和单企业部署边界。
- [ ] 准备本地依赖环境、配置示例、演示数据和测试数据隔离方案。
- [ ] 确认 Git 仓库位置与日常变更记录方式。

**交付物：** 环境启动说明、Agent 契约样本、基线检查记录、首批数据模型草案。

**验收：** 能重复运行旧问答流程；前后端工程检查结果有记录；不能运行的外部依赖有明确阻塞原因。模拟 Agent 仅用于独立测试，不替代真实联调验收。

### 阶段 1：登录、权限与应用框架

**目标：** 建立所有业务功能共用的身份和资源访问基础。

- [ ] Go 实现用户、登录、刷新、退出、当前用户与初始工作空间。
- [ ] 建立 Owner、Admin、Member 角色模型，以及知识库和本人会话的访问规则。
- [ ] 完成首批数据库迁移、连接生命周期、真实就绪检查和统一错误响应。
- [ ] 接入 Redis 登录限流等必要能力，定义 Redis 故障时的处理方式。
- [ ] React 完成登录页、受保护路由、应用布局、导航和统一状态展示。
- [ ] 明确 Query 缓存、认证内存状态与退出清理；统一基础视觉规范。
- [ ] 同步公开接口契约及认证、越权、刷新凭据轮换测试。

**交付物：** 可登录的应用外壳、身份权限基础、数据库迁移和认证接口。

**验收：** 未登录不能使用业务接口；退出和凭据撤销有效；错误凭据不泄露账号信息；切换身份不残留其他用户数据。

**范围控制：** 此时先完成权限基础，完整成员管理页面安排在阶段 5。演示账号通过明确的初始化流程创建，不设置隐藏登录后门。

### 阶段 2：打通真实流式问答

**目标：** 尽早完成 React → Go → Python Agent 的核心闭环。

- [ ] Go 封装 AgentClient，隔离旧协议、内部鉴权、错误和超时处理。
- [ ] 将已有测试知识库映射到平台并配置访问权限，不直接开放旧资源列表。
- [ ] 实现会话创建、本人会话列表、历史消息和运行记录基础数据。
- [ ] 实现提问前权限校验、授权知识库 ID 转换和同会话并发保护。
- [ ] 实现 SSE 转发，区分完成、失败、断流与结果未知。
- [ ] React 完成会话列表、问题输入、流式答案、停止接收和历史恢复。
- [ ] 展示受控的处理阶段与引用；不展示未经处理的内部推理文本。
- [ ] 测试半包、Unicode、重复事件序号、无 done 断流和退出时取消请求。

**交付物：** 可使用已有知识库回答真实问题的第一版聊天界面。

**验收：** 用户登录后能提问、收到流式答案、刷新查看历史；无权限知识库和他人会话不可访问；空授权集合被拒绝，不退化成全库检索。

**范围控制：** 暂不实现重新生成、自动重放、断点续传、多模态和 NL2SQL。停止接收不宣传为已停止模型计费，除非已经验证上游取消。

### 阶段 3：知识库与文档业务闭环

**目标：** 让管理员通过新平台上传资料，让员工据此问答。

- [ ] 完成知识库创建、列表、详情、权限配置和 Agent 资源映射。
- [ ] 完成文档上传、列表、处理状态、失败原因和切片查看。
- [ ] 验证文件大小、格式和实际内容，使用随机存储名及受限存储区域。
- [ ] 通过现有 Agent 上传接口与状态查询完成过渡版入库。
- [ ] 在授权知识库内解析引用，重名或无法唯一定位时明确失败。
- [ ] 完成文档删除与索引清理对账，防止处理中删除后重新出现在检索结果中。
- [ ] 补齐跨服务创建失败、请求超时结果未知与孤立映射的恢复路径。
- [ ] 完成“上传 → 处理完成 → 提问 → 引用 → 历史”的端到端测试。

**交付物：** 知识库管理页、文档管理页、授权引用查看及完整业务 MVP。

**验收：** 新上传文档可以被检索；未授权引用不可查看；删除文档完成清理后不可再检索；失败状态可以诊断。

**范围控制：** 此阶段使用旧 BackgroundTasks 的限制必须写在运行说明中，不能称为可靠队列。UI 查询任务状态先使用 React Query 轮询。

### 阶段 4：可靠异步入库与故障恢复

**目标：** 将过渡版上传升级为可恢复、可追踪的任务系统。

- [ ] 先写可靠任务 ADR，明确状态机、文件归属、幂等键、租约及迁移回滚方式。
- [ ] 在保留 Agent 算法的前提下设计 Python 入库适配层，支持按 job_id 提交、查询和复用结果。
- [ ] Go 实现 ingestion_jobs 与 Outbox 同事务写入。
- [ ] 实现 RabbitMQ 发布确认、消费者手动 ACK、有限重试和死信队列。
- [ ] 实现 Worker 并发上限、超时、租约、心跳、崩溃恢复与结果未知对账。
- [ ] 实现重复投递幂等、同键不同请求冲突处理和删除意图保护。
- [ ] React 提供任务阶段、尝试次数、可理解的失败原因及受控人工重试。
- [ ] 注入故障：发布后未记账、Agent 成功但响应丢失、成功后 ACK 前崩溃、处理过程中删除。

**交付物：** 真正工作的 Worker、队列与任务管理、Python 适配层、故障恢复报告。

**验收：** 重投不会重复创建文档副作用；崩溃后任务可恢复或进入可诊断终态；未知结果先对账而不是盲重试；永久失败不无限循环。

**范围控制：** 采用至少一次投递，不宣传端到端“恰好一次”。若坚持 Python 零修改，此阶段不能宣称完成，必须明确保留过渡版可靠性限制。

### 阶段 5：企业管理与产品体验

**目标：** 把已可用的问答工具完善为连贯的企业应用。

- [ ] 完成成员管理、角色调整、知识库授权及权限撤销。
- [ ] 完成运行记录、回答反馈、失败定位和关联请求 ID 展示。
- [ ] Go 提供授权范围内的调用量、成功率、延迟、任务状态等聚合接口。
- [ ] 使用 ECharts 构建统计页，提供空状态及文本或表格替代。
- [ ] 增加敏感管理动作审计；统计权限不隐含员工问答正文查看权限。
- [ ] 统一分页、筛选、错误提示、加载状态、键盘操作和响应式体验。
- [ ] 处理退出、权限变更和工作空间上下文变化时的请求取消与缓存清理。

**交付物：** 成员设置、运行记录、反馈与统计页面，一致的产品交互。

**验收：** 不同角色可操作范围符合权限矩阵；统计来自真实持久化摘要；无数据时不伪造图表；图表卸载后资源正确释放。

### 阶段 6：安全、部署与交付验收

**目标：** 让项目在干净环境中可复现部署，并具备基本运维能力。

- [ ] 完成前端、API、Worker、Agent 和依赖服务的 Compose 集成。
- [ ] Nginx 作为唯一公开入口；内部服务不直接暴露，SSE 关闭代理缓冲。
- [ ] 固定镜像版本、配置持久卷、健康检查、资源限制和优雅关闭。
- [ ] 完成秘密配置、上传与 Markdown 安全、限流、内部请求目标限制检查。
- [ ] 上线前关闭或隔离与企业知识问答无关的 NL2SQL 通路。
- [ ] 完善日志关联、依赖耗时、活动流、队列积压与失败状态观测。
- [ ] 补全 CI：类型检查、单元测试、构建、接口契约、真实依赖集成测试及关键 E2E。
- [ ] 验证全新数据库迁移、已有数据升级、备份恢复和版本回退流程。
- [ ] 编写启动、配置、排障、恢复和已知限制说明。

**交付物：** 可复现部署包、完整 README、CI 配置和发布验收报告。

**验收：** 按文档从干净环境完成部署与核心业务演示；重启后数据保留；备份可恢复；依赖故障可诊断；权限和故障测试通过。

**范围控制：** 首版是单机部署，不以 Compose 代替高可用证明。不安排 Kubernetes 或服务网格。

### 阶段 7：评测、性能与简历交付

**目标：** 用可复现证据说明项目价值和个人技术贡献。

- [ ] 建立非敏感企业演示资料、固定问题集和预期引用依据。
- [ ] 评估可回答、资料不足、引用错误、越权诱导等场景，记录失败案例。
- [ ] 使用模拟 Agent 测 Go 连接与流式转发能力，单独标注测试边界。
- [ ] 使用真实 Agent 测端到端延迟、首个答案 token 耗时、成功率和资源消耗。
- [ ] 记录硬件、数据规模、并发、版本、方法及 P50/P95 等测量结果。
- [ ] 根据测量结果选择优化项，保留优化前后同条件对比。
- [ ] 整理架构图、数据归属、SSE、权限与可靠任务的关键设计说明。
- [ ] 准备演示脚本、截图或视频、项目 README 和简历表述。

**交付物：** 问答评测集、压测报告、演示材料及有证据支撑的项目介绍。

**验收：** 可以说明“为什么这样设计、哪里会失败、如何恢复、如何测量”；每条性能结论都能追溯测试条件；既有 Agent 能力与本人新增工作明确区分。

## 7. 开发执行方式与变更控制

1. 每次选定一个阶段中的一个业务闭环，明确输入、输出、数据所有者和失败路径。
2. 先补公开契约与必要 ADR，再实现 Go 用例和 React 界面；可用受控替身开发，但真实联调是阶段验收条件。
3. 实现过程中同步覆盖正常、权限、异常及恢复场景，不把测试统一推迟到最后。
4. 每阶段交付代码、测试结果、演示步骤、已知限制和下一阶段入口。
5. 阶段切换必须经过验收，不以“页面能打开”或“接口返回 200”代替业务完成。

前端变更执行类型检查、测试和构建；用户旅程变更增加 Playwright。Go 变更执行格式化、vet、测试和构建，并发或异步变更增加 race 检查。数据库迁移和契约单独验证。受环境限制未运行的检查必须如实记录。

部署或迁移失败时，优先保持已有数据和已工作的业务入口：使用兼容迁移、功能开关或停止新任务入口；不要清空库、删除持久卷或将未知任务重新盲投作为恢复方式。可靠任务切换与数据所有权变化必须有独立迁移和回退设计。

TeamFlow 仅作为选定模块的参考来源。复用前检查具体实现、依赖方向、许可证及测试，不整仓复制，不以旧项目 README 代替验证。

## 8. 关键风险与处理原则

| 风险 | 处理原则 | 主要阶段 |
| --- | --- | --- |
| 现有 Agent 或模型不可用 | 先恢复真实基线；替身测试不代表联调成功 | 0、2 |
| 空知识库权限导致全库检索 | Go 默认拒绝，测试注入权限与 ID 转换 | 1、2 |
| 同名引用定位到其他资料 | 授权范围内解析，歧义失败，后续引入稳定 ID | 2、3 |
| SSE 中断仍显示回答成功 | 以 done 为完成依据，记录 interrupted | 2 |
| 跨服务创建超时且实际成功 | 记录未知结果、对账和补偿，不盲重试 | 2、3、4 |
| 重投造成重复文档或删除后重建 | Python 幂等适配、唯一约束和删除意图保护 | 4 |
| 统计泄露员工问答正文 | 聚合权限与正文权限分离，日志默认去敏 | 5、6 |
| 功能持续增加导致无法交付 | 先完成阶段 0～7；扩展集中放在阶段 8 | 全程 |
