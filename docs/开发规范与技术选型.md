# 企业内部知识库问答平台：开发规范与技术选型

版本：1.0 · 日期：2026-09-21 · 状态：前后端重写基线

本文固定项目技术栈、职责划分、接口约定和交付标准，供后续开发者及 AI 编码工具共同遵循。新增功能应遵守本文；改变数据归属、通信协议或基础设施选型时，先补充架构决策记录。

## 1. 产品目标与范围

建设面向企业员工的内部知识库问答平台。员工根据权限查询文档，获得流式答案和引用证据；管理员管理成员、知识库、文档处理任务，并查看调用质量和运行情况。

项目以 React 前端、Go 业务后端和复用的 Python Agent 组成。Go 是唯一公开业务入口，Python 负责现有 RAG 能力。保留现有项目作为行为参考，在新目录开发，不覆盖原 frontend/backend。

首版包含：登录与退出、工作空间与成员权限、知识库管理、文档上传和处理状态、会话与流式问答、引用查看、决策过程展示、运行记录、基础统计、Docker Compose 部署。

首版不包含：团队任务协作、支付计费、可视化工作流编辑器、自研模型训练、Kubernetes 集群、服务网格。多模态、NL2SQL 和高级检索实验台后置；企业知识问答上线前必须禁用或隔离现有销售数据 NL2SQL 通路。

首版文件存储采用持久化 Docker volume，存储访问封装成接口；对象存储作为后续替换项。Redis 不作为业务事实的唯一存储。Elasticsearch 继续保留，不能仅使用 MySQL 替代现有检索实现。

## 3. 架构与部署边界

```text
浏览器 React
    │ 同源 /api/v1，HTTP + SSE
Nginx → Go API → 内部 HTTP/SSE → Python Agent
           │                         │
      平台 MySQL、Redis          RAG MySQL、Elasticsearch
           │                         │
       Outbox → RabbitMQ → Go Worker → 入库适配接口
```

Go 采用模块化单体，API 与 Worker 可使用同一代码库的两个入口。Python 单独运行。首版不把认证、知识库、统计拆成多个微服务。

仅 Nginx 对外提供网页和业务接口；开发环境可按需绑定本机调试端口。Python、MySQL、Redis、RabbitMQ、Elasticsearch 放在内部网络。Go 调用 Python 必须配置连接超时、整体截止时间与内部鉴权。内部鉴权可先由紧邻 Agent 的内部代理校验服务令牌，避免为了接入改写 Agent 核心。

Docker 解决部署问题，不自动提供权限隔离、幂等、取消或高可用。Compose 单机部署不能在简历中直接表述为高可用集群。

## 4. 数据归属：优先复用现有 Agent

当前 Python 已持有 chat_session、chat_message、agent_decision_log、kb_database、kb_document、kb_chunk 等数据，并在问答过程中写库。首版保留这些事实，不安排 Go 与 Python同时写同一业务表。

| 数据 | 唯一写入方 | Go 的使用方式 |
| --- | --- | --- |
| 用户、工作空间、成员、登录会话 | Go | 自有模型 |
| 平台知识库与权限、Agent 资源映射 | Go | 鉴权并转换内部 ID |
| 平台会话归属、问答运行状态 | Go | 控制并发、映射 Agent 会话 |
| Agent 会话、消息、决策日志 | Python | Go 经内部接口读取 |
| RAG 文档、切片、向量与索引 | Python | Go 调用入库与查询接口 |
| 上传记录、任务、Outbox、审计、反馈 | Go | 自有模型 |

允许在同一个 MySQL 实例建立独立 platform 和 agent 数据库，使用各自账号。Go 不直接查询或修改 Agent 表。统计所需调用摘要由 Go 记录；不得再次保存一套独立可编辑的消息历史。

建议平台表：users、auth_sessions、workspaces、workspace_members、knowledge_bases、knowledge_base_members、document_bindings、chat_session_bindings、chat_runs、ingestion_jobs、outbox_events、processed_messages、audit_logs、answer_feedback。

映射包含平台 ID、workspace_id、agent_instance_id、agent_resource_id，以及创建状态。Agent 资源 ID 不作为浏览器端权限依据。跨服务创建采用 pending → ready/failed 和对账补偿，不宣称拥有跨服务数据库事务。

## 5. 权限与隔离

角色固定为 Owner、Admin、Member。Owner 管理工作空间和管理员；Admin 管理成员、知识库和文档；Member 只能访问被授权的知识库与本人会话。管理员查看员工问答正文需要独立明确权限，不能由统计权限隐含获得。

所有资源读写先校验工作空间成员身份，再校验资源归属和具体权限。所有查询在 Repository 层携带工作空间约束。前端隐藏按钮仅用于体验。

Go 必须把用户选择的知识库转换为经过鉴权的 Agent kb_ids。空权限集合直接拒绝请求，绝不能把空集合转换为 null，因为旧检索实现可能把 null 解释为全库检索。

现有 Python 不是多租户安全运行时。首版只开放单企业部署；平台数据从第一天携带 workspace_id，但未通过全链路隔离测试前不宣称支持多租户生产使用。未来多工作空间上线须选择并验证：每工作空间独立 Agent/存储，或增加 Agent 全链路强制 workspace 过滤。

现有引用通过文档名定位，存在重名歧义。Go 不得直接公开该全局查询接口；必须在授权知识库内解析引用并校验文档映射。无法唯一定位时返回“引用无法定位”，禁止猜测其他文档。后续适配返回稳定 document_id/chunk_id。

## 6. Go 与现有 Agent 的接口契约

所有旧接口只封装于 internal/agentclient，Handler/Service 不拼接 Python URL。AgentClient 必须可替换为测试实现。

| 能力 | 当前 Agent 接口 | 接入要求 |
| --- | --- | --- |
| 新建会话 | POST /api/chat/sessions | Go 保存会话映射及所有者 |
| 消息历史 | GET /api/chat/sessions/{id}/messages | Go 校验会话归属 |
| 提问 | POST /api/chat/sessions/{id}/ask | Go 注入授权 kb_ids |
| 知识库 | GET/POST /api/admin/kb | Go 管理映射和权限 |
| 上传文档 | POST /api/admin/kb/{id}/documents | 旧接口只代表接受处理 |
| 文档状态 | GET /api/admin/kb/{id}/documents | 对账 ready/failed |
| 查看切片 | GET /api/admin/kb/{id}/documents/{doc_id}/chunks | 校验库和文档映射 |

提问内部字段保持 question、kb_ids、skip_user_persist、images。公开首版只接受 question 和平台知识库 ID；内部参数由 Go 决定，客户端不能指定 skip_user_persist 或内部资源 ID。

同一 Agent 会话只允许一个活动运行，以数据库约束/事务为依据，Redis 可辅助。收到 409 时前端提示等待当前回答结束。首版重新生成后置，避免旧“删除最后一条回答”接口造成跨请求竞态。

普通只读接口可有限重试；创建资源、提问、上传在超时且结果未知时禁止盲目重试，进入对账状态。关闭前端连接会取消 Go 上游 HTTP 请求，但这不等于已经证明 Python 停止模型调用；必须通过集成测试验证，未验证时只承诺停止客户端接收。

## 7. SSE 规范

公开入口采用 POST /api/v1/chat/sessions/{id}/runs；浏览器使用 fetch + ReadableStream，不能使用只支持 GET 的原生 EventSource 直接提交问题。

保留旧事件名：router、rewrite、retrieve、grade、correct、generate、reflect、citation、done、error。Go 在前端事件中加入 run_id、request_id、递增 seq，隐藏或映射内部 message_id。未知扩展事件可忽略但必须记录，解析失败要结束运行并标记失败。

响应 Content-Type 为 text/event-stream，关闭代理缓冲并即时 Flush。解析器支持 UTF-8 跨块、CRLF、多个事件同块、多行 data 和半包；不能把一次网络 Read 当作完整事件。

HTTP 响应开始前可返回标准 JSON 错误；开始后使用 error 事件。收到 done 才算完成；没有终态的 EOF 记为 interrupted。run 状态包括 running、completed、failed、interrupted。首版不自动重放提问、不承诺断线续传。

React 将流式草稿保存在 Zustand，完成后刷新 React Query 消息历史，以 Python 持久化记录为准。必须阅读并测试旧生成阶段的替换/重写行为，不能默认所有 generate.delta 永远追加即可。

## 8. RabbitMQ 文档任务规范

分两步交付，避免把旧 BackgroundTasks 包装成“可靠队列”后误报完成。

第一步兼容接入：Go 调用旧上传接口并轮询状态，界面明确显示处理中。Python 进程重启可能中断任务，这是过渡版本限制。

第二步可靠入库：在保留解析、切块、嵌入算法的基础上，增加 Python 入库适配层，支持 job_id 幂等提交、查询结果、复用已创建文档。Go Worker 调用此接口。该适配是新增工作，现有 Agent 不具备这些保证。

任务流程：文件持久化 → MySQL 事务写 ingestion_jobs + outbox_events → 发布器投递 RabbitMQ 并等待 Confirm → Worker 处理 → 记录终态 → ACK。外部调用不放在长时间 MySQL 事务中。

消息至少包含 event_id、job_id、workspace_id、knowledge_base_id、file_ref、schema_version、trace_id、created_at。消息只保存引用，不携带文件二进制或密钥。

采用至少一次投递，按 job_id 与操作类型保证幂等；不能只依赖 Go 的 processed_messages 防止 Python 重复副作用。消费者崩溃在 Python 成功之后、ACK 之前时，重投必须查询/复用原结果。

状态：queued → processing → succeeded/failed；processing 记录 parsing/chunking/embedding/indexing 阶段。网络结果未知时进入 reconciling，由对账确认后再终结。自动重试有限次，耗尽进入死信队列；永久格式错误直接失败。记录 attempt、next_retry_at、last_error、心跳和租约，支持崩溃后恢复。

删除处理中文档须先记录删除意图，任务写回时校验版本或删除状态，避免删除后重新索引。任务进度首版使用 React Query 定时刷新，无需同时引入 WebSocket。

## 9. 前端开发规范

```text
apps/web/src/
  app/          # Router、QueryClient、全局 Provider
  features/     # auth、workspace、knowledge、chat、jobs、analytics
  components/   # 通用 UI
  lib/          # HTTP、SSE、日期等工具
  styles/       # Tailwind 与设计变量
  types/        # 公共接口类型
```

页面包含登录、知识库列表、知识库详情与上传、问答、运行记录、统计、成员设置。聊天页展示会话列表、流式答案、引用和可折叠决策事件，不展示未经处理的内部推理文本。

React Query 管服务端列表、详情、统计；Zustand 管流式草稿和跨组件交互；组件 useState 管局部表单；筛选和分页同步 URL。禁止将同一服务端列表同时保存到 Query 和 Zustand。

Query Key 包含 workspace_id 及查询条件。退出或切换工作空间清理敏感缓存并取消旧请求。API 类型优先从 OpenAPI 生成，禁止随意 any。React effect 必须清理订阅，组件挂载不得自动发送计费问答请求。

Tailwind 使用统一颜色、字号、间距和圆角变量。组件必须具备 loading、empty、error、disabled 状态及键盘可操作性。Markdown 禁止直接渲染未清洗 HTML。ECharts 封装组件负责 resize/dispose，按需加载；图表数据来自后端聚合，禁止前端拉全量问答日志计算。

## 10. Go 开发规范

```text
apps/api/
  cmd/api/              # Gin 启动入口
  cmd/worker/           # 任务消费与对账入口
  internal/
    auth/ workspace/ knowledge/ chat/ ingestion/ analytics/
    agentclient/ middleware/ config/ platform/
  migrations/
  api/openapi.yaml
```

按业务模块组织 Handler、Service、Repository。Handler 做解析和响应；Service 做权限与业务编排；Repository 做带作用域的数据访问；AgentClient 做旧协议适配。依赖在入口注入，禁止全局散落数据库和 HTTP 客户端。

GORM 操作传递 context，事务保持短小；唯一性使用数据库约束兜底。列表限制 page_size，排序字段白名单，禁止 SQL 字符串拼接用户输入。生产部署采用编号 SQL migration，不依赖 AutoMigrate 静默修改表。

HTTP 客户端复用连接，配置超时和连接池。SSE 整体截止时间须覆盖 Agent 配置的最大运行时间并留转发余量；不能套用普通短请求超时。goroutine 有退出条件，服务支持优雅关闭。密码使用 bcrypt。

登录采用短期 Access JWT（前端内存）与 HttpOnly 刷新凭据。刷新凭据服务端保存哈希并支持轮换/撤销；生产使用 Secure Cookie。Cookie 操作校验 Origin 与 CSRF，所有部署使用明确同源策略。业务接口仍以资源权限校验为准。

TeamFlow 可参考 JWT、权限、Zap、错误模型、Outbox 和幂等实现，但必须阅读具体代码、补测试后迁移；README 中“已实现”不等于已验证可靠性。

## 11. 公开 HTTP 约定

前缀 /api/v1，JSON 字段 snake_case，平台 ID 对外为字符串，时间为 UTC RFC3339。内部 Agent 数字 ID 在适配层转换。

普通成功响应：{"data":{},"request_id":"..."}；失败响应：{"error":{"code":"FORBIDDEN","message":"无访问权限"},"request_id":"..."}。使用真实 HTTP 状态码，不把全部错误包装成 200。分页 data 为 items、total、page、page_size，默认 20，上限 100。SSE 和文件下载不使用 JSON 包装。

| 路径 | 用途 |
| --- | --- |
| /auth/login、/auth/refresh、/auth/logout | 认证 |
| /users/me | 当前用户 |
| /workspaces/{id}/members | 成员管理 |
| /workspaces/{id}/knowledge-bases | 知识库列表和创建 |
| /knowledge-bases/{id}/documents | 文档列表和上传 |
| /ingestion-jobs/{id} | 入库状态 |
| /chat/sessions | 会话列表和创建 |
| /chat/sessions/{id}/messages | 历史消息 |
| /chat/sessions/{id}/runs | POST 流式问答 |
| /chat/runs/{id} | 运行状态与摘要 |
| /analytics/overview | 授权范围内统计 |

开发前补全 OpenAPI 的方法、字段、状态码和权限要求，SSE 事件另用 JSON Schema/示例描述。文件上传默认限制 20 MiB，并与现有 Agent 限制核对，取两端较小值；首版只支持 txt、md、pdf、docx。文件名不作为磁盘路径，使用随机存储名和受限下载入口。

## 12. 部署、观测与测试

Compose 包含 web/nginx、api、worker、agent、mysql、redis、rabbitmq、elasticsearch，为数据及上传目录提供持久卷。配置从环境变量读取，提交 .env.example，密钥不入库、不进镜像。健康检查区分存活和就绪，依赖失败可诊断；仅依赖启动顺序不能代替连接重试。

每个请求/任务贯穿 request_id、run_id/job_id。日志不记录密码、令牌或默认输出完整问题、文档和回答。第一阶段记录请求耗时、活动流、失败数、任务耗时、重试次数；后续接入 Prometheus/OpenTelemetry，不作为首个演示闭环的前置条件。

必须验证：

- 用户不能访问他人会话、文档、引用；空 kb_ids 不可变成全库检索。
- SSE 半包、Unicode、正常完成、错误、无 done 断流、同会话并发。
- RabbitMQ 重复投递、Worker 崩溃、Agent 超时但已成功、死信与人工重试。
- 上传后索引可查、删除后不可再检索、容器重启后数据保留。
- React 登录→上传→处理完成→提问→引用→历史消息的端到端流程。

CI 执行前端类型检查/测试/构建、Go 单元测试/编译以及依赖具备时的集成测试。性能测试分别使用模拟 Agent 测 Go 流式连接能力、真实 Agent 测端到端体验。记录硬件、数据规模、并发、P50/P95、错误率、首个答案 token 耗时；决策事件到达不能算作答案首 token。简历只能使用实际测量数据。

## 13. 实施顺序与验收门槛

1. **契约与基线**：整理旧 Agent 请求、响应、SSE 样本，确认模型和 ES 可用；固定依赖和新项目目录。验收：旧流程可重复运行。
2. **最小垂直闭环**：React 登录与聊天、Go 认证/会话映射/AgentClient/SSE，使用已有知识库。验收：回答与历史可见，权限测试通过。
3. **知识库管理**：React 上传和列表、Go 资源映射、旧 Agent 入库状态接入。验收：用户上传的文档可检索并查看授权引用。
4. **可靠任务**：RabbitMQ、Outbox、Python 幂等入库适配、Worker 与对账。验收：故障注入后无重复文档副作用、任务可恢复。
5. **产品与交付**：成员管理、统计/反馈、Compose、CI、端到端测试、演示数据与真实压测报告。验收：干净环境按 README 可部署，完整业务链可演示。

每阶段输出代码、测试证据、运行说明。首版目标是可演示、可解释、可验证的企业知识问答闭环；高级功能按已验证需求追加。

## 14. 后续编码约束
